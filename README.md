# CPU → 5050 LED 灯带 可视化系统

用 **UNO R3** 驱动一条 **WS2812B 5050 灯带**，在电脑上用轻量级客户端实时监测 **CPU 使用率** 并以 **平滑渐变的颜色** 显示出来。

系统由三部分组成：硬件连接、UNO 固件、Windows 客户端。

## 1. 硬件连接方案

### 1.1 硬件清单

| 名称 | 数量 | 说明 |
| --- | --- | --- |
| Arduino UNO R3 | 1 | 主控板 |
| WS2812B 5050 灯带 | 1 | 可寻址 RGB 灯带，建议 ≤30 颗（过长需外接电源） |
| USB 线 (A-B) | 1 | UNO 与电脑通信兼供电 |
| 面包板 + 杜邦线 | 若干 | 连接 |
| 220~470Ω 电阻 | 1 | DIN 信号线串联限流（可选但推荐） |
| 1000µF 电解电容 | 1 | 并联在灯带电源端（可选但推荐，防浪涌） |
| 5V 外接电源 | 1 | **灯带 ≥ 30 颗或超过 1 米时必须外接** |

### 1.2 接线表（WS2812B）

| WS2812B 灯带 | 接 UNO R3 |
| --- | --- |
| **VCC (+5V)** | UNO **5V**（短灯带） 或 **外接 5V 电源正极**（长灯带） |
| **GND** | UNO **GND**（必须与外接电源**共地**） |
| **DIN (数据)** | UNO **D6**（经 220Ω 电阻） |

```
 外接5V电源 + ──┬──── VCC(+5V) 灯带
               │
 外接5V电源 - ──┴──── GND 灯带 ──┐
                                 ├── UNO GND  （共地）
 UNO 5V ────────────────────────┘
 UNO D6 ──[220Ω]──── DIN 灯带
```

**要点：**
- **共地**：灯带与外接电源、UNO 必须共地，否则数据信号无法正确触发。
- **外接电源**：WS2812B 单颗全白约 60mA。30 颗全亮约 1.8A，远超 UNO 5V 输出能力，务必使用 5V ≥2A 电源，并 **只把 VCC 接外接电源、GND 与 UNO 共地**，**不要**把灯带 VCC 接 UNO 5V。
- **数据线**：DIN 不可接反，接错不亮；建议串联 220Ω 电阻保护引脚。
- **电容**：灯带电源两端并联 1000µF 电容，防止上电浪涌损坏灯珠。
- 本工程默认亮度为 25%（`BRIGHTNESS 64`），电流小、发热低，适合持续点亮。

### 1.3 可选：使用主板 5V3（5V 3 针 ARGB）接口

主板上的 **5V3 接口**即 **5V 可寻址 RGB（ARGB）接头**，三个脚为 **5V / DATA / GND**（不同主板排列不同，以主板手册为准）。它与 WS2812B 是**同一族协议**（单线可寻址、5V、约 800kHz NRZ），市面上大多数"5V ARGB 灯带"内部灯珠就是 **WS2812B**（或兼容的 SK6812），因此**可通用**。

**两种用法：**

1. **直连控制（不经过 UNO/ESP32）**
   把灯带 `VCC / DIN / GND` 直接接到主板 5V3 接头，用主板自带灯光软件控制颜色：
   - 华硕 Aura Sync / 微星 Mystic Light / 技嘉 RGB Fusion 等。
   - 优点：无需 MCU、无需串口客户端。
   - 缺点：颜色由主板软件决定，**无法实现"按 CPU 使用率映射颜色"的自定义逻辑**；如需程序实时控制，须借助 OpenRGB SDK 等额外开发，不在本项目默认范围内。

2. **只借用供电（数据仍由 UNO/ESP32 控制）**
   只取 5V3 的 **5V + GND** 给灯带供电，`DIN` 仍接 UNO `D6` 或 ESP32-C3 `GPIO5`：
   - 必须**共地**（灯带 GND 同时与电源、MCU 相连）。
   - **电流上限**：主板单个 5V3 接头通常额定 **3A**（部分主板 2A）。30 颗全白约 1.8A 可带；更长或接近 3A 时改用独立 5V ≥2A 电源。

> 结论：默认仍推荐 UNO/ESP32 方案（才能实现 CPU→颜色实时映射）；主板 5V3 可作为**供电来源**，或作为**由主板灯光软件直控**的替代方式。

## 2. UNO R3 固件

固件位于 [`R35050.ino`](R35050.ino)。

### 2.1 安装依赖库

1. 打开 Arduino IDE → **工具 → 管理库…**
2. 搜索 **FastLED** → 安装（作者 Daniel Garcia）

### 2.2 配置并烧录

1. 打开 `R35050.ino`，按实际情况修改两处配置：

   ```cpp
   #define NUM_LEDS  30    // 你的灯带灯珠数量
   #define BRIGHTNESS 64   // 全局亮度 0~255
   ```

2. 选择 **工具 → 开发板 → Arduino Uno**，**端口** 选择 UNO 所在 COM 口。
3. 点击 **上传** 烧录。
4. 烧录完成后保持 USB 连接即可。

### 2.3 固件行为

- 等待上位机发送颜色指令，收到 `R,G,B\n` 后整条灯带点亮为该颜色。
- 支持握手：收到 `?\n` 回复 `OK\n`，供客户端自动识别端口。
- **断连告警**：超过 3 秒未收到数据，灯带以 **50% 亮度慢闪红色**（完整闪烁约 1 秒）；收到任何数据后立即恢复正常颜色显示。
- 上电后若尚未有上位机连接，同样进入慢闪红色提示。

## 3. Windows 客户端

客户端源码位于 [`client/cpu_led_client.cpp`](client/cpu_led_client.cpp)，纯 Win32、无第三方依赖。

### 3.1 编译

✅ **已编译完成**：`client/cpu_led_client.exe` 已生成（MinGW-w64、约 206KB、单文件无依赖），可直接使用，也可从 [Releases](../../releases) 下载现成版本。程序为 GUI 子系统，运行时不弹出命令行窗口。

如需重新编译，二选一：

- **方式 A：MSVC（Visual Studio Build Tools）**
  安装后从开始菜单打开 **x64 Native Tools Command Prompt**，进入 `client` 目录运行：

  ```bat
  build_msvc.bat
  ```

- **方式 B：MinGW-w64（如 WinLibs / w64devkit）**
  将 g++ 所在 bin 目录加入 PATH 后，在 `client` 目录运行：

  ```bat
  build_mingw.bat
  ```

  w64devkit 命令行示例（`<w64devkit>` 换成你的解压路径）：

  ```powershell
  $env:Path = "<w64devkit>\bin;" + $env:Path
  cd client
  build_mingw.bat
  ```

生成单个可执行文件 `cpu_led_client.exe`（无任何依赖，体积约 206KB）。

### 3.2 运行

```bat
cpu_led_client.exe                # 正常启动，显示状态小窗
cpu_led_client.exe --hide         # 后台启动（开机自启时自动带此参数）
cpu_led_client.exe --port COM5    # 指定串口，跳过自动识别
cpu_led_client.exe --help         # 帮助
```

启动后会自动：
1. **自动识别串口**：遍历系统 COM 口并握手，找到 UNO；
2. **注册开机自启动**：写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，登录即后台运行；
3. 状态小窗实时显示 **CPU 使用率 / 当前颜色 / 串口连接状态**；
4. 最小化到**系统托盘**（图标），右键菜单可切换自启动、显示/隐藏状态窗、退出。

### 3.3 托盘操作

| 操作 | 功能 |
| --- | --- |
| 右键托盘图标 | 菜单：查看 CPU%、开关开机自启动、显示/隐藏状态窗、退出 |
| 双击托盘图标 | 显示/隐藏状态窗 |

### 3.4 轻量性说明

- 纯 C++ Win32，仅依赖系统库（GetSystemTimes/串口/托盘/GDI），无 .NET、无 JVM、无第三方运行时；
- 常驻内存约 **3~8MB**，CPU 占用接近 0（每秒采样一次 CPU、每 20ms 平滑并发送一次颜色帧，约 50 FPS）；
- 单实例保护，重复启动会自动退出。

## 4. CPU% → 颜色映射与平滑过渡算法

### 4.1 连续映射关系（分段线性，边界平滑过渡）

颜色以 6 个锚点做**连续分段线性插值**，任何相邻区间之间的颜色都不会突变；CPU 接近满载时红灯快速闪烁告警：

| CPU 使用率 | 颜色 | RGB |
| --- | --- | --- |
| 0 ~ 10% | 浅蓝（恒定） | `(135, 206, 235)` |
| 10 ~ 20% | 浅蓝 → 深蓝 线性过渡 | `(135,206,235)` → `(0,0,255)` |
| 20 ~ 50% | 深蓝 → 绿 线性过渡 | `(0,0,255)` → `(0,255,0)` |
| 50 ~ 80% | 绿 → 黄 线性过渡 | `(0,255,0)` → `(255,255,0)` |
| 80 ~ 100% | 黄 → 红 线性过渡 | `(255,255,0)` → `(255,0,0)` |
| 99 ~ 100% | 红 快速闪烁（告警） | `(255,0,0)` ↔ 灭 |

锚点：`0%→浅蓝`、`10%→浅蓝`、`20%→深蓝`、`50%→绿`、`80%→黄`、`100%→红`。相邻锚点之间按 CPU 比例线性混合（`Lerp`），因此 **浅蓝→深蓝、深蓝→绿、绿→黄、黄→红** 各段都平滑渐变；当显示 CPU 达到 **99%** 时，红灯以约 **150ms/档** 快速闪烁。

### 4.2 平滑过渡（显示 CPU% 平滑推进）

为避免颜色突变，客户端对**显示 CPU% 做平滑**，再由映射函数转成颜色：

- 每 **1000ms** 采样一次真实 CPU 使用率；
- 每 **20ms**（约 50 FPS）让"显示 CPU%"以固定速度向真实值靠拢：

```
display += sign(real - display) * CPU_SMOOTH_SPEED * dt    // CPU_SMOOTH_SPEED = 50%/秒
```

- 颜色由 `ColorFromCpu(display)` 实时算出，因此天然沿 **浅蓝 → 深蓝 → 绿 → 黄 → 红** 序列逐级推进；达到 99% 后转入红色快闪告警；
- 即便真实 CPU 从 **100% 骤降到 1%**，显示值也会依次经过 80→50→20→10，灯带**依次呈现 红、黄、绿、深蓝、浅蓝**，全程约 2 秒，无跳变；
- 采样/发送频率、平滑速度与快闪阈值均可在源码头部宏中调整（`CPU_INTERVAL`、`SEND_INTERVAL`、`CPU_SMOOTH_SPEED`、`BLINK_CPU_THRESHOLD`、`BLINK_INTERVAL_MS`）。

## 5. 通信协议

串口参数：**115200 baud, 8N1**。

| 方向 | 帧格式 | 说明 |
| --- | --- | --- |
| 客户端 → UNO | `R,G,B\n` | 设置整条灯带颜色，R/G/B 为 0~255 十进制 |
| 客户端 → UNO | `?\n` | 握手探测 |
| UNO → 客户端 | `OK\n` | 握手应答 |

客户端每 **20ms** 发送一帧（约 50 帧/秒），115200 baud 下流量可忽略。

## 6. 故障排查

| 现象 | 可能原因与处理 |
| --- | --- |
| 灯带不亮 | 检查 VCC/GND/DIN 接线；确认 DIN 接 D6；确认共地；短灯带确认供电是否足够 |
| 灯带慢闪红色 | 表示客户端未连接或未运行；启动客户端（或确认串口）后即恢复 |
| 只有前几颗亮或颜色乱 | 电压不足（灯带过长未外接电源），改用 5V 外接电源 |
| 状态窗显示"未连接" | 确认 UNO 已插 USB 且固件已烧录；可手动 `--port COMx` 指定；检查设备管理器 COM 口 |
| 颜色不变化 | 任务管理器观察 CPU 是否一直很低（<10% 恒为浅蓝）；尝试跑负载程序验证渐变 |
| 开机不自启 | 托盘菜单勾选"开机自启动"；或手动运行一次并退出 |
| 退出后残留托盘图标 | 鼠标悬停图标后消失（系统行为），不影响功能 |
